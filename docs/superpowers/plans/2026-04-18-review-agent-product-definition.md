# Review Agent 产品定义

> 本文档从产品视角描述 Review Agent 的定位、功能、使用方式与能力边界。
> 技术实现细节见 [current-architecture.md](../../current-architecture.md)，方向约束见 [direction-anchor.md](./2026-04-18-review-agent-direction-anchor.md)。

---

## 1. 一句话定位

Review Agent 是一个**自主译后审校与精修助手**——它读完小说初稿，自己发现问题、查证事实、精修译文、重译劣段、收尾未译、修整衔接、确认术语一致性，只在真正拿不准的时候才问人。

---

## 2. 解决什么问题

### 2.1 翻译初稿的系统性缺陷

一部 130+ chunk 的小说初稿，人工审校与精修面临五类系统性问题：

| 问题 | 人工审校的困难 | Agent 的优势 |
|------|--------------|-------------|
| **术语不一致** | chunk-3 译"Louki"为"露西"，chunk-45 又译为"露姬"，审校者很难逐 chunk 对比 | agent 可以跨 chunk 读取已确认术语表，自动发现不一致 |
| **上下文断裂** | chunk-12 结尾"他走进了教堂"，chunk-13 开头"她关上了门"——衔接是否合理？审校者需要反复翻前后 chunk | agent 可以同时读取前后 chunk，检查并修整衔接 |
| **事实性错误** | "1812 年拿破仑入侵俄国"——翻译是否准确？审校者不一定熟悉背景 | agent 可以查证知识库（后续可联网搜索），核实事实 |
| **未译残留** | 初稿中部分句子保留原文未译，或标注了占位符，人工容易遗漏 | agent 可以逐 chunk 扫描，发现并补译未译内容 |
| **译文质量参差** | 部分 chunk 翻译质量差（机翻痕迹、生硬表达、逻辑不通），需要精修甚至重译 | agent 可以评估每个 chunk 的策略（保持/轻修/深修/重译），针对性处理 |

### 2.2 人工审校与精修的规模瓶颈

- 130+ chunk 的初稿，人工逐 chunk 审校精修需要数天
- 审校者容易疲劳，后段 chunk 的审校质量下降
- 术语一致性需要全局视角，人工难以维持
- 衔接修改需要同时看前后 chunk，人工来回翻页效率低

## 3. 给谁用

### 3.1 主要用户

**翻译项目管理者**——负责翻译项目质量的人。他们：
- 启动 agent 对整个项目进行审校与精修
- 在 agent 请求帮助时提供决策（术语选择、风格偏好等）
- 审核 agent 的修订结果，决定是否采纳

### 3.2 使用场景

1. **全项目审校精修**：对整本小说初稿进行系统性审校与精修，产出每个 chunk 的修订稿
2. **定向审校精修**：对特定 chunk 或特定问题（如术语不一致、衔接断裂）进行审校精修
3. **术语确认**：agent 发现新术语时请求人工确认，确保全书术语统一
4. **收尾补译**：对初稿中保留未翻译的内容进行补译收尾

## 4. 核心功能

### 4.1 自主审校精修循环

agent 对每个 chunk 执行"发现问题 → 查证事实 → 评估策略 → 精修/重译 → 自检质量"的完整循环：

```
读取 chunk → 识别问题 → 查证（知识库/前后文/术语表）
    → 评估策略（保持/轻修/深修/重译）→ 执行精修或重译 → 自检
    → 满意则完成，不满意则继续取证
```

策略评估的四种结果：
- **KEEP**：译文质量合格，无需修改
- **LIGHT_EDIT**：小幅精修（术语替换、措辞微调）
- **DEEP_EDIT**：深度精修（逻辑重整、衔接修整、未译补全）
- **RETRANSLATE**：质量不达标，整段重译

### 4.2 跨 chunk 上下文感知

agent 不孤立地审校单个 chunk，而是：
- 读取前后 chunk 检查衔接
- 读取决策笔记理解上下文
- 读取过渡段检查连贯性
- 可扩展 working set 同时处理多个 chunk
- 发现衔接问题时直接修改过渡段

### 4.3 术语一致性保障

- 读取已确认术语表（`read_confirmed_terms`）
- 发现新术语时写入术语表（`record_confirmed_terms`）
- 后续 chunk 自动参照已确认术语
- 发现不一致时主动标记并修正

### 4.4 知识查证

- 搜索项目知识库（`lookup_knowledge_cards`，含向量检索）
- 查证人物关系、地名、文化背景等
- 后续可扩展联网搜索（`external_search`）

### 4.5 译文精修与重译

- **精修**（`draft_revision`）：基于审校发现的问题，生成修订稿
  - 术语替换：将不一致的译名统一为已确认术语
  - 措辞优化：改善生硬表达、机翻痕迹
  - 衔接修整：修正 chunk 间的过渡问题
  - 未译补全：补译初稿中保留原文的内容
- **重译**：对质量严重不达标的 chunk，整段重新翻译
- **自检**：精修/重译后自动检查质量，不满意的不会提交

### 4.6 逻辑检查

- 检查译文内部的逻辑一致性（因果、时序、指代）
- 检查跨 chunk 的逻辑连贯性（人物行为、场景转换）
- 发现逻辑问题时标记并尝试修正

### 4.7 求助式人工介入（待实现）

agent 遇到以下情况会主动问人：
- 术语选择不确定（如"这个地名应该音译还是意译？"）
- 风格偏好不明确（如"这段对话应该口语化还是书面化？"）
- 事实无法确认（如"原文这个历史事件的具体年份？"）
- 重译策略不确定（如"这段是保留原风格还是重新翻译？"）

人回答后 agent 自动继续，不需要手动恢复。

## 5. 输入与输出

### 5.1 输入

| 输入 | 来源 | 说明 |
|------|------|------|
| 项目初稿 | 翻译流水线产出 | 130+ chunk 的完整初稿（可能含未译残留） |
| 全局术语表 | 全局命名阶段产出 | `DraftStageGlobalGlossary` + `GlobalAliasConsistencyTable` |
| 项目知识库 | C0 阶段沉淀 | `KnowledgeCard` + `CandidateTerm` |
| 已确认术语 | 前序 chunk 审校时确认 | 译名表 |

### 5.2 输出

| 输出 | 说明 | 当前状态 |
|------|------|---------|
| 修订译文 | 每个 chunk 的精修/重译后译文 | ⚠️ 未落库（PassThrough） |
| 审校策略 | KEEP / LIGHT_EDIT / DEEP_EDIT / RETRANSLATE | ✅ 产出 |
| 过程摘要 | agent 的审校精修过程记录 | ✅ 产出 |
| 术语更新 | 新确认的术语/候选术语 | ✅ 写入术语表 |
| 人工求助请求 | agent 无法决定的问题 | ⚠️ 当前为排障式，待改为求助式 |

## 6. 工作流程（用户视角）

### 6.1 启动审校精修

```
用户 → 启动项目审校精修（projectId）
     → agent 自动选择第一个焦点 chunk
     → 开始自主审校精修循环
```

### 6.2 审校精修过程

```
agent 自主工作...
  ├─ 读取 chunk、发现问题、查证事实
  ├─ 评估策略（保持/轻修/深修/重译）
  ├─ 执行精修或重译、自检质量
  ├─ 满意 → 完成当前 working set → 选择下一个焦点
  └─ 不确定 → 请求人工帮助
              ↓
         用户收到求助请求
         用户回答问题
              ↓
         agent 自动继续
```

### 6.3 审校精修完成

```
agent 完成所有 chunk → 产出：
  ├─ 每个 chunk 的修订译文（精修/重译/保持）
  ├─ 每个 chunk 的审校策略和过程摘要
  ├─ 更新的术语表
  └─ 整体审校精修报告
```

## 7. 能力边界

### 7.1 能做什么

1. **发现翻译问题**：术语不一致、上下文断裂、事实性错误、风格不统一、逻辑矛盾
2. **精修译文**：术语替换、措辞优化、衔接修整、未译补全
3. **重译劣段**：对质量严重不达标的 chunk 整段重译
4. **保障术语一致**：跨 chunk 的术语统一
5. **查证事实**：基于知识库（后续可联网）
6. **逻辑检查**：译文内部和跨 chunk 的逻辑一致性
7. **自检质量**：精修/重译后的自检，不满意的不会提交

### 7.2 不能做什么

1. **不能替代人工判断**：术语选择、风格偏好等主观决策仍需人确认
2. **不能修改原文**：只修改译文，不修改原文
3. **不能重跑翻译流水线**：只能审校精修已有初稿，不能重新触发 A/B/C0/D
4. **不能自由联网**（当前）：联网搜索必须通过受控工具接口
5. **不能保证 100% 覆盖**：agent 可能遗漏某些问题，人工复核仍然必要

### 7.3 与人工审校精修的关系

agent 是**审校精修助手**，不是审校精修替代：
- agent 处理重复性、规模性工作（术语一致性、衔接修整、未译补全、事实查证）
- agent 处理技术性工作（精修措辞、重译劣段、逻辑检查）
- 人工处理判断性、创造性工作（风格偏好、文化适配、最终质量把关）
- agent 的修订结果需要人工审核才能最终采纳

## 9. 术语表

| 术语 | 含义 |
|------|------|
| chunk | 翻译单元，通常对应一个段落或几个段落 |
| working set | agent 当前正在审校精修的一组 chunk |
| focus anchor | agent 当前审校精修的起始 chunk |
| 精修 | 对译文的针对性修改（术语替换、措辞优化、衔接修整、未译补全） |
| 重译 | 对质量严重不达标的 chunk 整段重新翻译 |
| 术语表 / confirmed terms | 已确认的译名对照表 |
| 知识卡 / knowledge card | C0 阶段沉淀的结构化知识（人物、地名、文化背景等） |
| HITL | Human-in-the-Loop，人工介入 |
| 求助式 HITL | agent 主动问人，人回答后自动继续 |
| 排障式 HITL | agent 卡死等人排障，人诊断后手动恢复（当前状态，待改） |
| NO_PROGRESS | agent 连续 3 次被 guardrail 拒绝同一类操作，标记为无法继续 |
| guardrail | 执行层边界校验，防止 agent 做出越界操作 |
